NEXT STEPS:

1. Verify the operator is running:

   oc get pods -n {{ include "dpf-hcp-provisioner-operator.namespace" . }}

   You should see the controller-manager pod in a Running state.

2. Check operator logs:

   oc logs -n {{ include "dpf-hcp-provisioner-operator.namespace" . }} \
     -l control-plane=controller-manager -f

3. Verify the CRD is installed:

   oc get crd dpfhcpprovisioners.provisioning.dpu.hcp.io

4. Review operator configuration:

   A DPFHCPProvisionerConfig CR is deployed by the chart with defaults.
   The operator remains idle if this CR is deleted.

   oc get dpfhcpconfig default -o yaml

   To customize, patch the CR (e.g. change the BlueField OCP layer repo):
   oc patch dpfhcpconfig default --type=merge -p '{"spec":{"blueFieldOCPLayerRepo":"your-registry/repo"}}'

5. Create your first DPFHCPProvisioner custom resource

PREREQUISITES:

Ensure the following operators are installed on your management cluster:
- MCE Operator (Multi-Cluster Engine)
- DPF Operator (Data Processing Framework)
- HyperShift Operator
- ODF Operator (OpenShift Data Foundation)
- MetalLB Operator (if using LoadBalancer service type)

TROUBLESHOOTING:

- View operator events:
  oc get events -n {{ include "dpf-hcp-provisioner-operator.namespace" . }} --sort-by='.lastTimestamp'

- Check DPFHCPProvisioner status:
  oc get dpfhcpprovisioner -A
  oc describe dpfhcpprovisioner <name> -n <namespace>
